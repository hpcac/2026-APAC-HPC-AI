# OpenFOAM Application Notes: Iris

Practice on the **Iris** cluster so every team can learn this task and get hands-on before spending Gadi or ASPIRE-2A hours.

Iris times are not scored and are not compared with Gadi or ASPIRE-2A.

## What Iris is for

- Understand occDrivAerStaticMesh, v2512, the preparation chain, and simpleFoam logs
- Try decomposition and double-precision rebuilds without burning Gadi or ASPIRE-2A hours
- Do expensive profiling and tuning practice **here**, learning the tools. Do not burn Gadi or ASPIRE-2A hours on that path.

Work through the group example scripts on Iris:

`/global/exafs/groups/rdmaworkshop/2026hpcai-openfoam/reference-scripts/`

Those scripts are examples, not a required template. Do not run jobs out of the group tree; copy to your own work directory first (see the kit `README.md` on the cluster). After the group kit changes, `cd` to that work folder and run `~/00-sync-kit.sh` again.

## What not to copy onto the contest machines

The Iris example scripts use Iris queues, Iris MPI process counts (for example 56), and Iris run times. Use those numbers only on Iris. On Gadi or ASPIRE-2A the scored run is 4 CPU nodes; choose ranks and queues for that machine. Do not copy 56, or any other Iris number, as a rule.

The contest quantity is **average wall-clock time per time step**.

## The scored run follows the task rules

The charter is [2. OpenFOAM HPC Task Rules.md](2.%20OpenFOAM%20HPC%20Task%20Rules.md). Scored preparation follows [Allrun](https://develop.openfoam.com/committees/hpc/-/blob/develop/incompressible/simpleFoam/occDrivAerStaticMesh/Allrun) (`fvSolution.fixedIter`, `controlDict.noWrite`, `endTime` 40 / 80 / 150). Keep double precision. If a practice script skips a preparation step to teach a lesson, that skip is still not legal on a scored run. A single-precision (`WM_SP`) practice build is not legal on a scored run either.
