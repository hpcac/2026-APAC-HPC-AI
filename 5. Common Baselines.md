# 5. Common Baselines

One public performance baseline per task and platform, the same for every team. Please show the one for your platform in your interview slides, next to your own result, so that judges read every team's gains from the same starting point.

These are untuned runs: OpenFOAM with the site module and the case defaults, Qwen with the example layout from the Application Notes and default settings. They are a starting point, not a target; modest tuning usually beats them. Each platform has its own baseline, and platforms are not compared with each other. Every number comes from an Application Note or a logged run; the source is given.

## Other machines

If you could only use other machines (for example the Iris practice cluster or a university cluster), use your own untuned run on that machine as the baseline instead: site or stock build, case defaults, same node count.

## In your slides

Show the common baseline for your platform alongside your result, in whatever form suits your slides: a sentence, a row in your results table, a reference line or bar in a chart. Only the number and its source need to be clear. One way to write it: "4-node 2.03 s/step; common baseline (vanilla `scotch`, Gadi) 2.126 s/step (−4.5%)".

Keep your own baseline as well: it shows your path, and Bonus work is still measured against your own Basic result (README R3). If your own untuned run on the same platform differs from the common baseline, keep it as your own baseline and show both. This only asks for one more line in your slides, not for new runs.
